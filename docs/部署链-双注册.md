## 每次改 DLL 后的完整部署清单

1. 腾位 + 编译：`target\release\hufu_tsf.dll` → `.oldNN`，`cargo build --release -p hufu-tsf`
2. **32 位编译**：`cargo build --release -p hufu-tsf --target i686-pc-windows-gnu` → `target\i686-pc-windows-gnu\release\hufu_tsf.dll`
3. 同步打包源 `E:\DSH-KF\hufu-发行\打包源\`（hufu_tsf.dll + hufu_tsf32.dll）
4. 同步安装目录 `D:\HUFU\HuFu虎符输入法-v1.4.8-无模型\`
5. **UAC 提权覆盖 `C:\Windows\SystemIME\HuFu\hufu_tsf.dll`**（Start-Process powershell.exe -Verb RunAs；DLL 被加载中先腾位 .oldN）
6. **UAC 提权覆盖 `C:\Windows\SysWOW64\SystemIME\HuFu\hufu_tsf32.dll`**（t-deploy32-bom.ps1）
7. 用户重启目标应用；**验证=枚举进程模块路径 + DLL 时间戳**（编译了≠部署了）

## 教训

### 教训一（2026-09-08 上午）
2026-09-08 之前 7 项 DLL 修复全部只更新了 target\release 与打包源，
SystemIME 路径从未更新——edge 等系统进程一直跑 9 月 7 日旧版；跟打
器走 target\release 但重启前也跑旧文件。「编译+腾位+打包源同步」不
等于已部署，必须双路径覆盖 + 进程模块级验证。

### 教训二（2026-09-08 05:17）——32 位断供两天
用户换 32 位跟打器实测「打 100 多字即卡」；键盘钩子取证 663 键期间
虎符 trace 零行——SysWOW64 的 32 位 DLL 是 9/6 7:43 的 936KB 老版
（当夜 64 位已 12MB/9 项修复）。**改 DLL 只编 64 位=32 位宿主永远
老版**：32 位侧连接风暴/每键 GetTextExt×2/poll 白绘全部存活，且老
版无 trace（日志零行反而误导「DLL 未加载」）。32 位跟打器 100 字一
卡的根因即老版累积缺陷。修复：i686-pc-windows-gnu 重编+部署。

## 卡顿监控工具

`E:\DSH-KF\hufu-发行\t-monitor.ps1`（BOM 副本执行）：90s 实时增量读
`%TEMP%\hufu-tsf-trace.log`，输出每秒事件密度、>400ms 处理空窗、焦
点事件计数、消息 top。当日用它实锤 QQ 焦点风暴（40ms×8 OnSetFocus）
与键路径健康度（3ms/键）。

`t-sysmon.ps1`（全系统）：每 400ms 采样全部进程 CPU/线程/句柄差分
落 CSV——用它实锤 hufu-server 线程风暴（±7/秒）→ 管道每请求建连。

`t-hung.ps1`（UI 冻结探测）：SendMessageTimeout 350ms 探测宿主窗口
响应——用于排除「宿主 UI 挂起」假设（实测跟打器 UI 全程健康）。

`t-keylog2.ps1`（键盘钩子）：WH_KEYBOARD_LL 记录物理按键 epoch 毫秒
+ vkCode——与 trace dispatch 逐键比对定位键被扣环节。坑：wParam 是
消息类型（0x100/0x101=按下/抬起），vkCode 在 lParam 指向的
KBDLLHOOKSTRUCT 首字段（第一版记错全废）。
