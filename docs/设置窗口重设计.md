## 0. 一句话结论

把设置页重做成 **一套共享 Web UI + 两个平台薄壳窗口**：

- **Windows**：自写 Win32 窗口 + WebView2 宿主（`LoadLibrary` 动态载 `WebView2Loader.dll`，不依赖 MSVC / WinRT），替换现在“借 Edge `--app` 开网页”的做法；
- **macOS**：AppKit + WKWebView 薄壳（Swift），与 Windows 共用同一套前端；
- **视觉**：现代中性界面打底，以“墨底错金 / 合符 / 虎纹”做品牌线索，不把国风做成滤镜；
- **交互**：即时生效 + 状态可见 + 可撤销；只有两处保留显式“应用”（整句权重、同步凭据）；
- **预览**：DOM 手感层（0ms）+ 壁纸/棋盘背景 + “真机试打”（真实候选窗，100%）+ 悬浮预览窗（二期）四层，不再用 `getDisplayMedia` 抓屏；
- **迁移**：新壳 + 设计系统先行，按页面分批移植；旧页保留在 `/legacy` 一个版本周期。

预计：**P0 技术验证 1–2 天；P1 壳+核心页 1.5–2 周；P2 皮肤/挂件工作室 2–3 周；P3 键位/同步/数据 1–2 周；P4 macOS 对齐与发布 1–2 周**。实际排期取决于下面第 9 节要拍板的事项。

## 1. 现状诊断：为什么必须重做

现状不是“旧皮肤不好看”，而是四层问题叠在一起：

| 层 | 问题 | 证据 |
|---|---|---|
| 信息架构 | 8 个平铺 tab 装了 100+ 项，长说明直接堆在表单里；皮肤页内又套子分页 | 4270 行；`index.html` 258–852 |
| 交互语义 | 三套保存语义并存：400ms 防抖整包 POST、显式“保存并应用”、`onchange` 直存；同一皮肤页里颜色直存、滑杆防抖 | 1406–1418、1576、1767–1772 |
| 工程结构 | 单文件、无构建、209 处内联 style、111 行超 200 字符、最长 1482 字符；按键编辑器整窗 HTML 由 1400 行字符串拼成，靠 `window.open` 寄生 opener，设置页一关就变死键 | 3738–3982、3912 |
| 外壳与品牌 | Edge `--app` 无窗口控制、无图标、依赖用户装了 Chromium；macOS 不可用；`hufu.ico` / `hufu-icon-256.png` 等品牌资产在设置页零引用；0 个 `aria-*` / `tabindex` / `focus-visible` | main.rs 698–756；审计第 5、6 节 |

功能本身没有大问题，**不能推倒重来**。新 UI 必须以现有 8 页功能全集为验收基线（见 5.10 与附录 C），逐页迁移。

## 2. 设计原则

1. **一屏一件事，渐进披露**：一页只回答一个问题；300 字说明进“?”帮助浮层或抽屉，不再铺在表单之间。
2. **即时生效，状态可见，可撤销**：能热更新的全部自动保存；页面头部常驻“已保存 / 保存中 / 失败”；破坏性操作给撤销 toast。
3. **真机为准，预览分层**：DOM 只负责“调参手感”，最终以真实候选窗/真实渲染帧为准；界面必须明确告诉用户当前是哪一层。
4. **平台原生，界面同构**：窗口、菜单、文件对话框、快捷键尊重平台；内容与交互一套。
5. **品牌克制**：90% 是功能界面，10% 才是虎符；Q 虎头、虎纹、合符只在关键节点出现，不做满屏青铜纹理。

非功能底线：键盘可达、对比度 AA、`prefers-reduced-motion`、200% 缩放、窗口最小 900×600、首屏 < 800ms。

## 3. 品牌与视觉概念

### 3.1 概念：错金 · 合符

- **错金**：虎符是青铜铸虎、错金铭文。取“墨（近黑）+ 青铜灰 + 错金”做主色，金色只做强调，不做大面积背景。
- **合符**：虎符一分为二，合而为信。云同步页用它做状态语言：两半符靠近=同步中，合拢+金缝=已同步，分开+断口=出错。这是整个设置里最有记忆点的品牌表达，且**功能上成立**（双机同步）。
- **虎纹**：三道渐收的斜纹，做页头/空状态的低透明度装饰，不做按钮纹理。
- **品牌图标**：按用户拍板，采用 **Windows 安装器当前版 Q 版虎头**（`platform/windows/setup/icons/虎符.ico`，8/29）。设置窗内把它放在**深色印章底 + 细金边**的圆角方块里，26/44px 仍可读；关于页可用 96–128px 原图。9/25 的 Linux「符」字艺术图（`platform/linux/branding/hufu.png`）保留为备选/次级品牌，不进入本轮主界面。
- **合符**：云同步页把 Q 虎头**一分为二**，中间一条错金缝，两半合拢=已同步、分开=异常；比抽象的“符节”图形更像虎符，也直接使用了图标本身。

### 3.2 色彩 tokens

暗色为默认设计基准，浅色是同一套语义的换值（不是简单反色）。

| Token | 暗色 | 浅色 | 用途 |
|---|---|---|---|
| `--bg` | `#131417` | `#F5F2EA` | 窗口底 |
| `--surface` | `#1C1F24` | `#FFFFFF` | 卡片 |
| `--surface-2` | `#23272E` | `#F1ECE1` | 输入框/次级块 |
| `--line` | `#2C313A` | `#E2DCCE` | 分隔线 |
| `--line-strong` | `#3B414C` | `#CFC6B4` | 悬停/聚焦边框 |
| `--text` | `#F0EDE6` | `#211E18` | 主文字（暖白/墨） |
| `--text-2` | `#A8A49B` | `#6D675B` | 次级 |
| `--text-3` | `#77746D` | `#9A9385` | 占位/弱提示 |
| `--gold` | `#E7B75C` | `#A8741A` | 品牌强调/选中/CTA |
| `--gold-strong` | `#F3C877` | `#8A5E12` | hover/文字金 |
| `--gold-soft` | `rgba(231,183,92,.12)` | `rgba(168,116,26,.10)` | 选中底/高亮底 |
| `--bronze` | `#8A6A3F` | `#7A5A32` | 辅助插图/半符 |
| `--patina` | `#5E8C7E` | `#3F7264` | 极少量辅助（云状态第二色） |
| `--red` | `#E06A5A` | `#B84534` | 危险/错误 |
| `--green` | `#63C08D` | `#2F7D55` | 成功 |
| `--blue` | `#6AA6FF` | `#2F6FCB` | 信息/链接 |
| `--focus` | `#F3C877` | `#8A5E12` | 焦点环 |

规则：
- 金色**不用于错误/警告**；错误一律红，成功一律绿。
- 浅色下金色文字必须用 `--gold-strong`（`#8A5E12`），`#E7B75C` 在白底不可读。
- 主按钮：暗色=金底墨字；浅色=深金底白字；次按钮=透明底+边框；危险按钮=红字/红底只在确认框里。
- 大面积背景只允许：纯色、极轻的径向暖光（不超过 6% 透明度）、虎纹 3% 透明度。禁止青铜渐变铺满。

### 3.3 字体与排版

- UI：`-apple-system, "SF Pro Text", "Segoe UI Variable Text", "Segoe UI", "PingFang SC", "Microsoft YaHei UI", "Noto Sans SC", sans-serif`
- 等宽：`"Cascadia Mono", "SF Mono", Consolas, monospace`（编码/路径/版本）
- 字号：12 辅助 / 13 说明 / 14 正文与控件 / 15 强调 / 17 节标题 / 22 页标题 / 28 关于页主标题
- 行高：正文 1.55，标题 1.3；中文不额外加字距，英文标签可用 0.02em
- 数字用 `font-variant-numeric: tabular-nums`（滑杆值、大小、进度）
- 不引第三方中文 Web 字体；“虎符”字标用 SVG 路径或系统字重 650，避免 SimSun 的老气

### 3.4 圆角、间距、层次

- 间距基数 4：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48
- 圆角：控件 6、卡片 10、弹层 14、窗口 8（Win）/ 10（Mac）、胶囊 999
- 阴影只给浮层：`0 16px 48px rgba(0,0,0,.38)`；卡片靠 1px 边框和表面色分层，不堆阴影
- 页面内边距 32（窄屏 20）；卡片内边距 20；表单行纵向 12，组间距 24
- 内容最大宽 1040；皮肤/挂件工作室全宽（预览区优先）

### 3.5 图标

- 统一 20×20 网格、1.6px 描边、圆角端点；导航 18px
- 用 Lucide 图标子集 + 8 个自制品牌图标：虎头、半符、合符、符节（设备）、印（恢复默认）、刷（皮肤）、挂件、键盘
- **彻底移除 emoji 图标**（📂📤☁ 等）；emoji 只在正文语义需要时保留
- 图标按钮必须有 `aria-label` + tooltip；tooltip 不能是唯一说明

### 3.6 动效

| 场景 | 时长/曲线 |
|---|---|
| 页面切换 | 180ms `cubic-bezier(.2,.8,.2,1)`，内容淡入 + 4px 上移；侧栏选中条 160ms 滑动 |
| 二级页/Sheet 进场 | 220ms 弹簧（stiffness 380 / damping 32），8–12px 位移 + 淡入；退场 140ms |
| 弹窗/确认框 | 160ms 淡入 + scale .98→1 |
| 开关/滑杆 | 开关 150ms；滑杆拖动不加过渡（避免跟手迟滞） |
| Toast | 180ms 滑入，4s 自动消失 |
| “已生效”印章 | 240ms scale 1.06→1、rotate -6°→-3°，600ms 后淡出 |
| 同步合符 | 成功时两半符 260ms 合拢，金缝亮一下；失败只做 120ms 抖动 |

- 全部动效在 `prefers-reduced-motion: reduce` 下降为 100ms opacity（或直接无动画）
- 候选窗动效在“皮肤工作室”里可“重播”，用配置里的速度倍率，不另造一套节奏
- 动效只做 transform/opacity；不做大面积 blur 动画

### 3.7 窗口外观

**Windows**
- 默认 1080×720 DIP，最小 900×600；记住位置/大小/最大化；多屏按工作区 clamp
- 自定义标题栏 44px：左 虎头 26（深色印章底）+ “虎符设置”13 + 分隔线 + 当前页名 12（次级色）；右 最小化/最大化/关闭 46×32
- Win11：DWM 圆角 + Mica 背景（标题栏/侧栏可见区域）；**不假设 WebView2 能透出 Mica**——若 spike 证明不能，就用同色实底 + 极轻渐变，标题栏单独 Mica
- Win10：方角 + 亚克力失败则纯色；深色标题栏随主题
- 拖拽：标题栏与侧栏顶部用 `ReleaseCapture + WM_NCLBUTTONDOWN`；双击最大化；Snap Layouts 作为二期（`WM_NCHITTEST` 返回 `HTMAXBUTTON`）
- 任务栏图标 = 虎符 ico；无控制台窗；单实例，第二次启动只聚焦

**macOS**
- 默认 1080×720，最小 900×600；`titlebarAppearsTransparent + fullSizeContentView`，标题隐藏，交通灯内嵌在侧栏左上（左内边距 78）
- 侧栏用 `NSVisualEffectView`（`.sidebar` 材质）做 vibrancy；WKWebView 背景透明，内容区用实底
- 顶部标准菜单：关于虎符设置 / 设置…（⌘,）/ 隐藏 / 退出；编辑菜单（撤销/复制/粘贴，保证输入框可用）；窗口菜单
- 文件选择/保存走 `NSOpenPanel` / `NSSavePanel`；外部链接走默认浏览器
- 关闭最后一个窗口即退出设置 app；输入法本体仍在

- 顶部：皮肤名（可改）、保存状态、`…`（恢复出厂/导出 weasel/删除）

  - 材质 12 项、布局 13 项、间距 5 项、序号 6 项、颜色角色 21 项

- 每个分组标题右侧“恢复本组默认”
- 所有滑杆：拖动本地 60fps，停止 150ms 后 PATCH；失败回滚 + toast
- 状态条：`已保存 · 候选窗同步中…` → `已同步`（SSE 收到 skin_ver 或 2.5s 轮询兜底）
- macOS：预览按 NSVisualEffectView 材质语义近似（solid/translucent/frosted/glass），页脚标注“macOS 近似预览”；颜色/布局/字号仍按同一皮肤参数。真正的 Mac 候选窗效果以 `CandidatePanel` 为准，P4 提供“Mac 真机试打”

**SSF 模式**
- 中：皮肤预览图 + 九宫格 mock 文字（`/api/skin/ssf-mock`），可切真帧校验
- 右：字号、字体、横竖排、显示序号、候选高度（±100，滑杆+数字框联动）、4 个文字色覆盖、还原皮肤原值、删除
- 顶部：启用独立皮肤开关（明确“启用后走位图皮肤”）；显示解析警告；注明“皮肤文件由用户自备”

**A/B**：按住“原样”显示已保存版本，松开回编辑版；二期做左右分屏拉杆。

**空状态/错误**：无皮肤、导入失败（列出 warnings）、渲染失败（降级 DOM + 提示）。

## 6. 交互与实时机制

### 6.1 保存语义（统一矩阵）

| 对象 | 语义 | 反馈 |
|---|---|---|
| 全局 config（方案/输入/候选/挂件等） | 200–300ms 防抖，PATCH 局部字段 | 页头“已保存”；失败回滚 + toast |
| 皮肤参数 | 拖动本地即时；停止 150ms 后 PATCH；A/B | “已保存 · 候选窗同步中 → 已同步” |
| 键位 | 改动即存（200ms） | 页头/键帽即时更新；冲突提示 |
| 整句权重/高级 | **staged 草稿 + 显式应用** | 底部 sticky “有未应用调整” |
| 云同步凭据 | **显式保存并测试** | 行内测试结果 |
| 导入/删除/重置 | 确认 Dialog | toast + 撤销（可撤销的才给） |
| 主题 | localStorage 即时 | 无网络 |

**版本与冲突**：`GET /api/config` 带 `rev`；`PATCH /api/config` 带 `rev`，冲突返回 409 + 最新 `rev`/config；前端提示“设置已在别处更新”并刷新。这样解决现在“整包 POST 把别处改动覆盖回去”的老问题（旧页曾因整包回写把皮肤选择写回旧值）。

**撤销**：破坏性操作（删除皮肤、清空回收站、恢复默认、导入覆盖）成功后 toast 带“撤销”（本地快照回滚）；普通调参不做全局撤销，靠分组重置/A-B。皮肤编辑器二期加本地历史栈（Ctrl+Z 只在非输入框生效）。

### 6.2 预览四层

| 层 | 技术 | 延迟 | 保真 | 用途 |
|---|---|---|---|---|
| L1 DOM | CSS/DOM 按皮肤参数绘制 | 0ms | 中（字体度量/九宫格近似） | 拖滑杆的即时手感 |
| L2 背景 | 棋盘 / 深/浅 / 桌面壁纸（读系统壁纸 + CSS 模糊） | 0ms | 中 | 透明度/毛玻璃观感 |
| L3 真机 | 在设置窗内放输入框，真实 TSF/IMK 候选窗出现 | 即时 | 100% | 最终验收、字体/行高/位置 |
| L4 真帧 | 现有 `ssf-render`（SSF）或未来 Rust 渲染（矢量） | 2–3s / 10–40ms | 高 | 位图皮肤校验、导出缩略图 |
| L5 悬浮窗 | 独立置顶透明窗（P2） | 即时 | 高（真实桌面合成） | 验证透明/毛玻璃 |

- **不再使用 `getDisplayMedia` 抓屏**：在 WebView2/WKWebView 里权限与反馈回路都不可控；改为读系统壁纸 + CSS 模糊，悬浮窗验证真实合成
- “真机试打”是零成本的 100% 保真：设置窗本身就是输入框，输入法会画真实候选窗；只需给一块示例区+提示
- 拖动滑杆时只走 L1；停手 150ms 后 PATCH；SSE/轮询拿到 `skin_ver` 后显示“候选窗已同步”；真实候选窗本身 ≤2.5s 跟随
- 位图皮肤：L1 用 `ssf-mock` 元数据 + border-image；点“校验真帧”才调 `ssf-render`（2–3s），不阻塞编辑
- 矢量皮肤将来若要做 L4，可把皮肤布局抽成 Rust 共享布局模块输出绘制指令，再做 CPU/GPU 两个后端；这是 P3 之后的投资，不是 v1 必需

### 6.3 实时通道

- **一条 SSE** `GET /api/events`，事件：`config`（rev）、`skin`（ver/id/kind）、`sync`（state/progress）、`engine`（model/schema）、`theme`（可选）
- 心跳 25s；最多 4 条连接；断线指数退避（1s→8s），连续失败降级为 1s 轮询 `/api/state`，并在页面显示“实时已断开”
- **不用 WebSocket**：现有 HTTP 服务每连接一线程，WS 要手写握手/帧解析/掩码，收益不抵成本
- 聚合启动：`GET /api/bootstrap` 一次拿 about/platform/config/rev/schemas/skins/state/sync，减少首屏瀑布
- 输入框打字不轮询：SSE 推状态，或输入事件本地处理

### 6.4 主题与平台

- 默认 `prefers-color-scheme`；三态切换（跟随/浅/深）；localStorage 记忆；切换时给 `<html data-theme>` 加 120ms 颜色过渡（禁用时无）
- Windows 标题栏深色同步（DWM）；Mac `NSAppearance`
- 高对比度模式：边框加粗、金色文字换 `--gold-strong`；减少透明度
- 平台差异通过 `window.__HUFU_PLATFORM__` 与 `/api/platform` 下发（os、titlebar inset、modifier 名称、是否支持原生保存对话框）

## 7. 技术架构

### 7.1 总览

```
┌──────────────────────────── Web UI（共享，Vite 构建）────────────────────────────┐
│ React 19 + TS + Radix + Motion + CSS tokens；hash 路由；API client；SSE          │
└───────────────▲──────────────────────────────────────────────▲──────────────────┘
                │ http://127.0.0.1:4390（同源）                  │
        ┌───────┴────────┐                              ┌──────┴────────┐
        │ Windows 薄壳    │                              │ macOS 薄壳     │
        │ hufu-settings   │                              │ 虎符设置.app    │
        │ Win32 + WebView2│                              │ AppKit+WKWebView│
        │ 自写 COM FFI    │                              │ Swift          │
        └───────▲────────┘                              └──────▲────────┘
                │ 启动/聚焦 IPC（命名管道/单实例）                │ LaunchServices
        ┌───────┴───────────────────────────────────────────────┴────────┐
        │ hufu-server（常驻）：引擎 + 现有 REST API + 新增 SSE/PATCH/静态资源 │
        └─────────────────────────────────────────────────────────────────┘
```

### 7.2 Windows 外壳

**推荐：自写 `hufu-settings.exe`（x86_64-pc-windows-gnu）**

- Win32 顶层窗口（`WS_OVERLAPPEDWINDOW` 或 `WS_POPUP|WS_THICKFRAME` 自绘标题栏）、Per-Monitor V2 DPI、圆角、主题
- WebView2：`LoadLibraryW("WebView2Loader.dll")` → `GetProcAddress("CreateCoreWebView2EnvironmentWithOptions")`；COM 接口用 `#[repr(C)]` vtable 手写（ICoreWebView2Environment/Options/Controller/WebView2/Settings/EventHandler 等）。**不引 `windows` 0.61 / WinRT**——本机 spike 已证明它会拖入 `api-ms-win-core-winrt-error-l1-1-0.dll` 并在 Windows 11 26300 启动失败；手写 FFI 与现有 TSF COM 同构，可控
- 用户数据目录：`%LOCALAPPDATA%\HuFu\WebView2`（避免落在 exe 旁/被清理）
- 单实例：命名互斥体 + 隐藏消息窗/命名管道 `\\.\pipe\hufu-settings`；第二次启动发“聚焦/跳页”后退出
- 打开流程：托盘/热键/`设置.bat` → `hufu-settings.exe --tab=skin`；已开则聚焦并切页
- WebView2 运行时检测：`GetAvailableCoreWebView2BrowserVersionString`；缺失→引导安装 Evergreen Bootstrapper（或回退 Edge `--app`，保底）
- 发布物：`hufu-settings.exe` + `WebView2Loader.dll`（x64，约 200KB）；安装器/便携 zip 都带；不进 TSF DLL
- 标题栏：先用“自绘 HTML 标题栏 + JS 拖拽桥”做视觉统一；spike 若 Snap Layouts/最大化动画不可接受，退回原生标题栏 + Mica（功能不受影响）

**为什么不是 Tauri/wry**：Tauri 官方不支持 GNU 工具链（社区讨论 #14350），本机无 MSVC；实测最新 wry+tao **能编译**，但启动即因 WinRT API set 缺失失败（见附录 D）。手写 WebView2 宿主与项目现有 Win32/COM 风格一致，体积增量最小（≈200KB + 宿主）。
**为什么不是 Electron**：+80–150MB，与发行包目标冲突。
**为什么不是纯原生 WinUI3/SwiftUI**：两套 UI 写两遍，21 个颜色角色/大量动态表单成本过高；预览还要另做。

### 7.3 macOS 外壳

- 独立 `虎符设置.app`（Swift，AppKit + WKWebView），bundle id `im.hufu.settings`；也可被输入法菜单唤起
- `NSWindow`（fullSizeContentView + 透明标题栏 + 交通灯内嵌）；侧栏 vibrancy；WKWebView `drawsBackground = false`
- `WKUserContentController` 桥：窗口控制（关闭/缩放/置顶）、打开外部链接、原生打开/保存面板、壁纸、主题、复制诊断；`WKDownloadDelegate` 处理下载
- ATS：`NSAllowsLocalNetworking` / localhost 例外；仅加载 `127.0.0.1:4390`，外链交给浏览器
- 引擎：launchd LaunchAgent 常驻（随登录启动）；设置 app 启动时探测 `/api/health`，失败则尝试 `launchctl kickstart` 或拉起 `hufu-server`，显示品牌化“引擎未启动”页 + 重试
- 输入法菜单：`HuFuInputController.menu()` 增加“设置… / 关于虎符 / 检查更新”；全局热键 `⌃⌥H`（可选）
- 安装包：`.dmg` 含 `HuFuIME.app`（输入法 + server）与 `虎符设置.app`；`~/Library/Input Methods/` 安装说明；签名 + 公证（需要 Apple Developer ID；没有的话先给未签名包+右键打开说明，并在方案里标风险）
- 与 Windows 的差异只在壳：同一份前端、同一套 API；平台标识注入 `window.__HUFU_PLATFORM__`

### 7.4 前端

- **React 19 + TypeScript + Vite**；Radix UI primitives（Dialog/Sheet/Popover/Select/Switch/Slider/Tabs/Tooltip）保证可达性；Motion 负责路由/Sheet 动效；CSS 变量 + CSS Modules（**不用 Tailwind**，避免类名汤与设计 token 两套真源）；Lucide 图标子集 + 自制 8 个
- 路由：hash（`#/skin`），二级页 push；旧 `#tab=` 映射；页面级 `React.lazy` 分包
- 状态：`ConfigProvider` 持有 config + rev；`useConfigSection` 选择器；乐观更新 + PATCH + 409；`useDebouncedCommit`；SSE 更新外部变更
- API client：`get/patch/post`、错误归一化（`{code,msg}`）、重试（仅幂等 GET）、加载/错误/空态 hooks
- 组件库：见附录 B；每个组件有键盘/焦点/禁用/错误态；页面用统一 `PageHeader`/`Section`/`Row`
- 字体/图标/资源全部本地，不引 CDN；CSP 默认只允许 self
- 目标：首屏 JS < 250KB gzip；工作室内存 < 80MB；拖动 60fps（transform/opacity，避免整页重排）

### 7.4.1 无构建 vanilla（已做可交互演示）

- 演示：`docs/design/vanilla-demo.html` + `demo.css` + `demo.js`，纯 HTML/CSS/JS，**零依赖、零构建**；双击打开即可。
- 已实现：hash/侧栏切页、三态主题、皮肤预设（墨言/雨竹/鲸语）、预览背景（棋盘/深/浅/壁纸）、透明度/圆角/阴影滑杆实时改候选窗、A/B、按钮 toast。
- 结构：单页 + CSS 变量 + `data-*` 属性 + 事件委托；生产可拆成 `pages/*.js`、`components/*.js` 的 ES modules，仍然不需要构建。
- 成本：状态、弹层焦点、键盘可达性、表单校验、渲染性能都要手写；10+ 页和 21 色编辑器会显著膨胀，回归靠约定与测试。
- 结论：演示证明“视觉可以完全一致”；**已定生产用 React**（组件/状态/可达性/测试生态），vanilla 作为零 Node 的备选/对照 demo。

### 7.5 服务端改动（保持旧 API 兼容）

| 新增 | 说明 |
|---|---|
| `GET /api/bootstrap` | 聚合 about/platform/config+rev/schemas/skins/state/sync |
| `GET /api/events` | SSE（config/skin/sync/engine）；心跳 25s；上限 4 连接 |
| `PATCH /api/config` | JSON Merge Patch + `rev`；409 冲突；旧 `POST` 保留 |
| `GET /api/config` 加 `rev` | 现有 UI 不受影响（多一个字段） |
| `GET /api/health` | 壳探测；版本/端口/引擎状态 |
| `GET /api/wallpaper` | Windows 读系统壁纸路径返回图片（可选；Mac 走壳桥） |
| `POST /api/skin/render` | （P2 可选）矢量皮肤真帧 PNG；先用现有 ssf-render 覆盖位图 |
| 静态资源 | `/assets/*` 带 hash 长缓存；`/` 新 UI；`/legacy` 旧页；SPA fallback |

- SSE 实现：`http::serve` 增加流式响应分支；广播用 `std::sync::mpsc` 订阅者表 + 清理；每连接一线程可接受（设置窗通常 1–2 个连接）
- 配置写入仍走 Host 锁；PATCH 只合并指定路径；数组整体替换；皮肤版本自增逻辑不变
- 安全：保留 Origin/Host 校验；新增 PATCH/SSE 同样校验；外链白名单；CSP；不引入远程内容
- 兼容：旧页继续可用；新页读同一 config；两版并存一个版本周期

### 7.6 构建与发行

- `hufu/settings-app/`：`package.json` + Vite + TS；`pnpm build` 产出 `dist/`；**dist 提交进仓库**（release 机不需要 Node）；CI/本地脚本校验 dist 与源码一致
- `hufu-server` build.rs 把 `dist` 编译进二进制（生成 `include_bytes!` 表；不引额外 crate）；旧 `index.html` 继续 include 到 `/legacy`
- Windows：新 crate `platform/windows/hufu-settings`；`cargo build --release --target x86_64-pc-windows-gnu`；发行脚本增加该 exe + `WebView2Loader.dll`；`设置.bat`/快捷方式/托盘/热键改走它
- macOS：扩展 `platform/macos/build.sh` 编译 `虎符设置.app`；**universal2**（arm64 + x86_64，server 也按双架构构建或随包各带一份）；签名/公证脚本；dmg
- 版本：设置窗口标题/关于页从 `/api/about` 取版本；不单独维护 UI 版本
- 回滚：`/legacy` + 安装包保留旧页；出问题可让用户用 `?ui=legacy` 或回退版本
- 测试：Rust 单测（PATCH/SSE/静态路由）；Playwright 用独立 `--data/--port` 起测试 server，截浅/深/窄屏/各页；键盘导航；对比 DOM 预览与真帧（SSF）容差

### 7.7 性能与安全预算

- 首屏：HTML+CSS+JS < 350KB gzip；首屏可交互 < 800ms（本地）
- 页面切换 < 100ms；滑块拖动无掉帧；皮肤页大图 lazy
- SSE 1 连接；页面隐藏时暂停轮询/动画
- 无远程字体/脚本；所有导航限制在 127.0.0.1；外链 `noopener`；下载内容大小限制；皮肤/挂件图片继续走现有白名单与大小校验
- 设置窗不持有管理员权限；安装器 UAC 只用于安装
