候选窗皮肤梳理

数据源：真机 D:\HuFu\数据\皮肤（打包时整目录覆盖打包源，这套就是发出去的那套）。
所有候选窗都按 hufu-skin 的真实字段渲染，字号、圆角、内边距、选中块逐项取自各自 JSON。

一、现状：21 款并排

同一块背景、同一字号，只看一件事：你的眼睛能不能一眼落在选中项上。 下面组里默认放在「暖色桌面」上——真实使用最常见的场景。

二、诊断：选中块与底色的反差

这是「选中项在哪」的唯一客观指标。行业里一个实心选中块至少要 1.6 才扫得出来， 低于 1.3 基本等于没有。这 21 款里绝大多数在 1.2–1.5。

另：alpha 是 back_color 的底色不透明度。Windows 已不提供背景模糊， 凡是低于 0xE0 的，桌面会原样透进来，字色与底的对比度取决于壁纸——等于不可控。

三、新方向：从设置窗 token 派生

设置窗 CSS 里已经有一套 token：墨 #131417、金 #e7b75c、暖白 #f0ede6。 候选窗直接继承它，就自然跟整套软件是一家人。四款两个明暗配对，都是 不透明底 + 实心选中块。

四、规范

层级角色规则门槛
1底色 back_color必须不透明（alpha = FF）。要半透明就得有模糊，而模糊已经退役。—
2选中块 hilited_candidate_back_color实心，与底反差不低于 3:1。深色底用金色，浅色底用青铜或墨。≥ 3.0
3正文 candidate_text_color始终可读，不随选中与否大幅改变字重。≥ 7.0
4注释 comment_text_color比正文低一档，但拼音在 10px 下也得认得出。≥ 4.5
5序号 label_color未选中时故意压低，选中时随块走。允许低于正文。≥ 2.5
命名规则：色名 · 变体，不再混用「写意色名」和「功能描述」。
例如「迷雾改」「玻璃横排」「全透明横排」这类名字应当退役；「晨白 · 朱砂」「夜航 · 银沙」这种已经在正确的路上。
