## 3.【功能】重复上屏可用任意标点顶上屏

- **现状**：`{重复上屏}` 只能通过码表编码 + 空格/数字选重上屏（`lib.rs`
  `resolve_dynamic` 展开 `last_commit`）；编码态标点走"标点顶字"（提交首选
  候选 + 标点），功能词候选与标点顶字未打通。
- **要做**：功能词候选（{重复上屏}/{撤回} 等）接入标点顶字路径——
  **例：z1 是 {重复上屏}，按 z 再按任意标点（，。、；等）= 重复上次上屏内容 +
  该标点**，与普通候选的标点顶字语义完全一致。
- **验收**：码表 `z1 {重复上屏}`，打 z 后按任意标点都顶上屏「上次内容+标点」；
  普通候选标点顶字行为不变。
- **批次**：第一批。

## 4.【功能】多轮重复上屏：{重复上屏2} {重复上屏3} 派生功能词

  （`host.rs` 每次上屏收口覆写，只记文字部分）；`resolve_dynamic` 只认
  `{重复上屏}` 一个标签，无历史概念。
- **要做**：

    挂码到任意编码；

  `{重复上屏3}`→A；历史不足时对应候选不出现；现有 `{重复上屏}` 行为不变。

## 6.【功能】Esc 双行为：有候选清屏 / 无候选撤回上次上屏（开关，默认关）

- **现状**：`lib.rs` `KeyCode::Escape`：raw 非空 → 清屏；空态 → 透传。没有撤回，
  也没有开关。
- **要做**：
  - **设置页加开关，默认关**：
    - 关（默认）：Esc 只有清屏效果（现行为不变）；
    - 开：有候选按一次 Esc 清屏；**无候选按一次 Esc 撤回上一次上屏内容**；
  - 撤回基于 `last_commit` 长度发回删，复用 `KeyOutcome.back` 机制（"1.→。"已在用），需确认 DLL 侧对长文本回删的 EditSession 路径；
  - 与"延迟重载"的交互（Esc 触发 pending reload 的既有路径）不能破坏；
  - 连续撤回语义（撤完一次再按 Esc 是否撤更早一条，可联动第 4 项历史栈）与用户拍板。
- **验收**：开关开时，上屏「我们」后空态按 Esc 两字消失，有编码时只清屏；开关关时 Esc 永不撤回（空态透传）；默认安装为关。
- **批次**：第一批。

## 7.【功能】撤回做成 {撤回} 功能块，可在码表里自由加入

- **现状**：功能词机制已成熟：`{重复上屏}`（展开回放）、`{加词}`/`{隐藏候选}`（DLL 拦截不上屏）、`{日期}`族（实时展开）。无撤回。
- **要做**：
  - 新增 `{撤回}` 标签：提交时不输出文本，产出 `back = 上次上屏文字长度` 的回删指令（口径与 `last_commit` 只记文字一致——撤文字不撤尾随标点）；
  - host 收口：`{撤回}` 不进 `last_commit`/`tail_context`（同 `{加词}` 白名单）；
  - 候选显示层给功能提示（如「↩撤回」）；
  - 用户即可在码表里自由挂码（例：`/ch {撤回}`）。
- **验收**：码表加 `/ch {撤回}`，上屏「你好」后打 /ch 空格，「你好」被回删；重复上屏/尾巴语境不受污染。
- **批次**：第一批。

## 8.【BUG】不同桌面缩放比例下，跟打器里候选不跟光标（晴跟打 pro、虎魄跟打器）✅ 已完成（2026-10-05，v1.7.0）

- **BUG·高优**（与第 2 项并列的两个 BUG 之一，最后做）。
- **现状**：跟打器宿主的候选定位靠 est 估算链（`tsf.rs` `est_step` + `query_caret`）：
  锚点（首键 GetTextExt/selection 真实帧）→ 每键步进（unit_w 自适应，未校准退
  0.41×行高）→ 折行（前台窗宽-160、行首缩进 24[跟打器]/90[普通]、折行步长
  1.42×行高）→ Y 钳制（宿主窗底）。虎魄走「恒定锚」模式（GetTextExt 恒定值、
  段内零查询），晴/pain 走 est 链。**关键问题：这些魔法数（160/24/90/1.42/0.41）
  全是 100% 缩放下实测标定的裸物理像素常数，锚点/步进/折行链完全没有 DPI
  换算**——渲染侧有 dpi_scale（GetDpiForWindow，含 HUFU_FAKE_DPI 测试旋钮），
  定位侧没有。
- **疑点**（诊断分叉）：
  - ① 常数未随缩放换算：125%/150% 下行宽余量、缩进、步长、折行步长全偏 → 步进漂、折行提前/滞后、候选滞留上一行；
  - ② 坐标虚拟化：跟打器进程 DPI 感知等级与系统/其他屏不一致时，GetTextExt/GetWindowRect 返回被虚拟化的坐标，锚点本身就错位；
  - ③ 多显示器混合 DPI：主屏 100% 副屏 150% 类场景锚点跨屏错位。
- **要做**：
  - 复现矩阵：100%/125%/150%/200% 各档 × 晴跟打 pro + 虎魄，抓 trace 定位漂移环节（锚点/步宽/折行/Y 钳制哪一环错）；
  - 修法方向：est 链全部像素常数按宿主窗实际 DPI 缩放（GetDpiForWindow(foreground)）；或把 unit_w 的"真实帧自适应校准"思路推广到行宽/缩进/折行步长（免维护常数）；
  - 核查跟打器进程的 DPI 感知上下文（per-monitor v2 等），虚拟化场景做坐标还原；
  - 给锚点链补 HUFU_FAKE_DPI 100%~500% 缩放矩阵桩测。
- **验收**：100%–200% 各档（+混合 DPI 双屏），晴/虎魄打字候选全程贴光标：不漂、不滞留上一行、不飞屏、折行正确。
- **批次**：第二批末位（**BUG，最后做**；第一批功能验证通过后先做 2，再做本项）。

## 9.【功能】「`」加入编码字母表可作引导打特殊字，与反查解冲突

- **现状**：反查引导键 `config.reverse.prefix`（默认 `` ` ``，小写态进反查）；
  **编码态按 ` = 顶首选+「·」**（`lib.rs`【` 顶屏 2026-09-06】分支，置于
  alphabet 判定之前，` 永不当编码字符）——所以用户把 ` 加进设置页「编码字母表」
  （`input.alphabet`）也不生效。反查关闭时另有 `reverse.disabled_output` 直出
  语义，与本项交叠。
- **要做**：
  - 让 ` 可作**引导键**打特殊字（部分用户的 ` 引导习惯）；
  - **优先级规则（用户口径）**：默认编码字母表无 `、反查开着 → ` 现行为不动
    （反查引导/编码态顶屏·）；**仅当用户把 ` 加入编码字母表 且 关闭了反查功能
    后，` 引导才生效**；
  - 实现：` 在 alphabet && 反查关闭 → 走引导/编码路径；否则维持现分支；
  - 设置页文案提示：「要启用 ` 引导，请把 ` 加入编码字母表并关闭反查」。
- **验收**：默认配置 ` 仍进反查；把 ` 加入字母表并关闭反查后 ` 引导可打出特殊字；反查重开后 ` 恢复反查引导。
- **批次**：第一批。
