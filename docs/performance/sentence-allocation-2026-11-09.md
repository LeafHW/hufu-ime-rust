# 整句临时分配实验与未采用结论（2026-11-09）

本轮基于概率查询复用提交 `47aacdc2`，依次试验 A：删除 `early_mass`，B：再用 `get_mut` 原地更新 `Bucket::add`，C：再借用父桶。最终三项实验均未采用，源码保留 `47aacdc2` 的原有实现，前一轮概率查询缓存完整保留。分配减少和部分场景更快，没有满足本轮对性能回退的门槛。

决定不采用 B 的直接证据是最终全套普通输入、提前上屏开启时，P95 两轮由 12.8408 / 12.8856 升至 13.6855 / 13.4256 ms；整组进程 CPU 时间由 20.719 / 21.953 变为 21.297 / 21.453 s，一升一降，压力组也有逆向。专用长输入的改善不能抵消这些结果，也不能证明所有场景都不回退。因此 A/B 不额外落地，较早撤回的 C 也不采用。

B 实验版在提前上屏关闭的逐键探针中，29～49 键输入的 alloc/alloc_zeroed 调用减少 9.01%～9.89%，累计请求字节减少 1.91%～2.13%；11 键分别减少 5.45% / 2.25%，128 键分别减少 7.04% / 2.62%。这些是未采用实验的分配结果，不是已进入产品的优化。C 的普通、12 worker、固定单核、专用长输入及分配数据保留在[未采用父桶借用实验附件](sentence-borrow-experiment-2026-11-09.md)。

开发、探针和测试在独立 C: 工作树进行。DSH 跟打器、原工作区和安装文件未改。B 实验版的 170 项测试、真实轨迹差分和 server release 构建均通过；这些检查证明覆盖范围内结果一致，不保证性能没有回退。未运行 server 构建产物，也未部署到安装版。

## A/B 实验内容（均未采用）

`early_mass` 原先在完整态和不完全尾状态中查询、调用 `logsumexp`、复制文本键并写入；该表没有被读取到候选、置信度、排序或返回结果中。A 实验删除这张局部表及其独有计算，保留实际选择候选的 `early_best`；最终源码恢复原实现。

B 实验中的 `Bucket::add` 先借用 `item.text` 查询可变状态，按原顺序计算 `prev_mass` 和 `newm`，按原 `max_rank` / `score` 条件替换状态，再写回同一个 `newm`。唯一文本分支将最后一份已拥有的键移入 `best`。同文平分仍保留先到路径，较低 `max_rank` 仍硬优先，`limit` 清空质量表后的回退仍使用旧状态中已聚合的 `mass`。HashMap 的既有键和 `order` 保持原有行为。

普通组整组 CPU 为 A 轮升高、B 轮降低，两轮合计约升高 0.18%；压力组 CPU 两轮降低约 7.4% / 2.0%。普通输入、提前上屏开启时，P95 两轮由 12.841 / 12.886 升至 13.686 / 13.426 ms，约回升 6.58% / 4.19%；mean 一升一降，P50 也一升一降。这不能称作普通输入稳定提速。普通长组字的 mean / P90 / P95 则两轮降低，与定向长组字试验方向相符。

用户要求不能影响整句性能。本轮没有得到足以满足该约束的稳定全场景证据，因此 B、C 都未采用；A 单项只验证了结果和分配成本，没有单独完成耗时门禁，也没有仅凭“少做工作”直接落地。实现已恢复为 `47aacdc2`，前一轮概率缓存保持不变。实验二进制、源码备份和全部正反向结果留作后续定位资料。


## 准确性证据与输入域

B 实验版检查记录为 `next-bucket-final-tests.txt`：hufu-engine 111 个单元测试、23 个集成测试，hufu-sentence 36 个测试，共 170 项全部通过。新增桶差分测试保留原 `Bucket::add` 作为对照，逐位比较所有状态字段、best/mass/order/truncated 和 snapshot 顺序；覆盖重复优劣、平分、名次优先、不同词边界和补充词状态、limit 后质量回退、清空重插及固定种子随机操作。

实验回退后，该测试源码保存为 `.review/sentence/bucket_add_tests.rs`，没有作为当前源码的新增测试保留。当前引擎文件已与 `47aacdc2` 核对一致。

特殊浮点测试将两种不同符号和 payload 的 quiet NaN、正负无穷、正负零及有限值用于 score/mass 组合，只测试 add 和 snapshot，不调用 limit 或排序。既有整句测试继续覆盖全量/增量桶、五阶历史、BOS/EOS、未知字、非 BMP 字符、同文质量、选重、数字码、用户词更新、剪枝和模型家族。

B 实验版真实模型轨迹 `next-trace-bucket.jsonl` 与基准 `next-trace-before.jsonl` 都为 2,186 条、38,522,857 字节，输出完全一致，SHA256 为：

`a2b3745e7d1dd04962c6d15a6853095f0274e3b826763400c89f6fa6bff7e6ad`

轨迹比较所有候选字段、score/confidence 位、截断标记、按键消费、上屏/回删、剩余编码及公开 Session 状态；检查的 158,388 个 score/confidence 值均有限。B 实验版的 server release 构建通过，没有运行或部署产物。

## 测量方法与统计口径

环境和隔离方法沿用[概率查询复用报告](sentence-latency-2026-11-09.md)：Rust 1.98.1、opt3、fat LTO、单代码生成单元；码表 112,622 条，NM03 Q8/version 2 模型 405,663,171 字节。固定语料与 raw 生成规则不变，rich/full/Engine 缓存隔离，用户词注入在测量窗外完成，关闭学习、调频日志、神经重排和 OpenCC，使用专门数据目录。

计时与分配计数使用独立构建。计时关闭 `alloc-count`；分配二进制不用于推断耗时。全套普通/12 worker 对照先预热再测三轮，按原版 A、B 实验 / A、B 实验 / B、原版 B 执行，保留逐键样本、mean 和各分位数；专用长输入另用 20 轮。测量期间不并行编译或运行其他性能任务。

普通组只表示未另加专门的竞争负载，没有控制所有系统后台活动。分位数使用排序样本的 `floor(n × q / 100)` 下标，上限为 `n - 1`；mean 和累计耗时使用全部有效样本，原始逐键顺序另存。进程 cycles 来自 Windows `QueryProcessCycleTime`，不是指令数，不能直接换算为某个按键的加速比例。

计数器包装 Rust `GlobalAlloc`，结束计数先读入标量，再构造 JSON，四阶段资料均修复了报告自身分配混入统计的问题。

- `allocs` 统计成功的 alloc/alloc_zeroed，reallocs 单列；两者不能混为一个未说明的分配次数。
- `requested_bytes` 累加每次 alloc 的 Layout 大小和每次 realloc 的整个 new_size，是累计请求量，不是同时占用量或复制字节；原地扩容同样记 realloc。
- `peak_extra_rust_heap_bytes` 是窗口内逻辑 Rust 请求堆峰值减去起点活跃请求堆，不含模型 mmap、Win32 分配器元数据、页面驻留情况或底层 realloc 搬迁的旧新块短暂并存，不能换算 RSS。
- Engine 窗口覆盖整条逐键流程，也包含探针 input(raw) 临时 Vec 的固定开销；直接全量解码在清缓存和注入后开始，两类结果分别报告。
- allocs 与 frees 的差额不代表泄漏，缓存、结果和 Session 可在窗口之后释放；计数器是进程全局的，当前探针用于关闭后台学习和重排的受控单线程比较。

## 原始资料与后续候选

资料保存在当前工作树忽略目录 `.review/sentence/`：`next-probe/` 为探针与计数器；`next-alloc-before.jsonl`、`next-alloc-deadmass.jsonl`、`next-alloc-bucket.jsonl` 为基准和B 实验的分项计数；`next-summary.jsonl` 同时保存各版本相对基准的原始变化。`next-alloc-after.jsonl` 属于未采用 C，解释和旧计时表见附件。B 实验的测试/轨迹文件与专用长输入文件见上文，失败与逆向结果均保留。

后续方向包括子状态 String/Vec 克隆时预留追加容量、利用词边界累计字数减少文本扫描，以及真实宿主中的完整输入链路。每项都需要独立的分配、耗时和逐位差分证据；本轮三项未采用的结果说明，源码上更少的复制并不足以证明没有性能回退。当前独立引擎探针仍不覆盖物理击键到 TSF 宿主可见候选和上屏的完整延迟。
