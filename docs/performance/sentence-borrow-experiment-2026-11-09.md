# 未采用的父桶借用实验（2026-11-09）

本附件记录已撤回的 C 三项合并版：删除 `early_mass`、`Bucket::add` 原地更新、主循环通过 `split_at_mut` 借用父桶。本轮最终 A/B/C 均未采用，源码保留 `47aacdc2`，结论见[主报告](sentence-allocation-2026-11-09.md)。本附件的 `after`、C 实验版和三项合并版都指未采用的 C，不能混作 B 两项实验的数据。

父桶借用按 `order` 读取未变化的当前桶并写未来桶，曾通过结果差分，也减少临时分配；但分配下降没有转化为稳定的长输入延迟改善。普通短轮测量已经出现长组字 P95 两轮回升，随后专用 20-repeat ABBA 中 mean 两轮增加 1.81% / 1.47%，P90、P95 也均回升，CPU 时间和 cycles 方向混合。最终撤回父桶借用，保留原有 snapshot 深拷贝路径。

下方旧表和解释完整保留，均明确属于未采用 C 版。其计时和分配方法、统计口径沿用主报告；特别是累计请求量不等于同时内存占用，计数二进制不用于测量耗时。

## 三项合并实验的实现与分配记录

`early_mass` 原先在完整态和不完全尾状态中反复查询、调用 `logsumexp`、复制文本键并写入；它没有被读取到候选、置信度、排序或返回结果中。本轮删除这张局部表及其独有计算，保留实际用于选择候选的 `early_best`。

`Bucket::add` 原先先复制 `item.text`，查询旧状态，必要时重新插入更优状态，最后再次查询并写入聚合质量。现在先以 `item.text` 借用键调用 `get_mut`；按原顺序计算 `prev_mass` 和 `newm`，按原 `max_rank` / `score` 条件替换状态，再写回同一个 `newm`。唯一文本分支将最后一份已拥有的键移入 `best`。同文平分仍保留先到路径，较低 `max_rank` 仍硬优先，`limit` 清空质量表后的回退仍使用旧状态中已聚合的 `mass`。

主循环原先调用 `Bucket::snapshot()`，先深拷贝整桶状态，再为每个被接纳的子路径克隆一次父状态。每个 `St` 的深拷贝包含文本 `String` 和词边界 `Vec`。C 实验用 `split_at_mut(pos + 1)` 将父桶与未来桶分开：按原 `order` 逐项查询 `best`，借用父状态，只为子路径保留必要的克隆。构段保证 `end > pos && end <= n`，子路径只写未来桶；父桶在整轮展开期间不变。遍历顺序、缺失键处理和增量恢复的 `skip_upto` 判断保持原样。

分项二进制按下列顺序累计改动。`bucket` 包含 `deadmass`，`after` 包含全部三项；下表各列不能作为独立降幅相加。表中每个数字为清空解码缓存后的一次直接全量解码，`allocs` 不包含另记的 `reallocs`。

| 阶段 | 30 键 allocs | 30 键累计请求字节 | 128 键 allocs | 128 键累计请求字节 |
|---|---:|---:|---:|---:|
| `before`：`47aacdc2` | 60,430 | 12,876,767 | 249,468 | 105,039,748 |
| `deadmass`：删除无效质量表 | 60,022 | 12,827,710 | 249,160 | 104,955,717 |
| `bucket`：再原地更新同文状态 | 53,881 | 12,638,404 | 220,946 | 102,224,360 |
| `after`：再借用父桶展开 | 48,558 | 11,326,141 | 198,115 | 92,118,636 |

删除无效表可以消除一部分确定的冗余工作；原地更新进一步减少文本键复制；父桶借用同时省去状态文本和词边界复制，累计请求字节的下降主要在该阶段体现。这些分项结果用于确认成本来源，端到端耗时仍需由不带分配计数的二进制独立测量。

## C 阶段准确性检查记录

相关测试共 170 项通过：hufu-engine 111 个单元测试、23 个集成测试，hufu-sentence 36 个测试。新增桶差分测试保留原 `Bucket::add` 作为对照，实际调用新实现，逐位比较所有 `St` 字段、`best` / `mass` / `order` / `truncated` 和快照顺序。覆盖唯一文本、重复路径更优/更劣/平分、名次硬优先、不同词边界与补充词状态、`limit` 后质量表清空、`limit(0)`、重新插入，以及四个固定种子的小规模随机操作。

特殊浮点测试将两种不同符号及 payload 的 quiet NaN、正负无穷、正负零和有限值用于 score/mass 组合，保留原浮点位，逐次比较 add 和 snapshot；它不调用 `limit` 或排序。已有概率缓存差分测试继续覆盖全量/增量桶、五阶历史、BOS/EOS、未知字、非 BMP 字符、同文质量聚合、选重、数字码、用户词更新、剪枝和模型家族。

原版与 C 实验版真实模型轨迹均为 2,186 条、38,522,857 字节，输出完全一致，SHA256 为：

`a2b3745e7d1dd04962c6d15a6853095f0274e3b826763400c89f6fa6bff7e6ad`

轨迹比较全部候选字段、score/confidence 位、截断标记、按键消费、上屏/回删、剩余编码和公开 Session 状态。检查的 158,388 个 score/confidence 值均为有限数。

行为等价结论针对正常有限配置和本次真实轨迹。现有提前候选排序将 NaN 的 `partial_cmp(None)` 当作相等后再比较文本，与有限值混合时不能构成全序；删除一张局部 HashMap 也可能改变后续哈希种子及排序前的遍历顺序。本轮没有扩张对任意非有限配置的等价性承诺，也没有修改该既有排序边界。桶 add 的特殊浮点测试不能替代整个引擎在该输入域的证明。

### 整组进程时间

整组时间还包含模型/方案装载、直接解码、注入词和所有逐键场景。它与某一键的延迟分别报告；CPU 时间不包含负载程序。单位为秒，仍按 A / B 排列。

| 环境 | 原版 CPU | C 实验版 CPU | 原版墙钟 | C 实验版墙钟 |
|---|---:|---:|---:|---:|
| 普通 | 23.297 / 19.828 | 21.469 / 18.938 | 23.978 / 20.124 | 22.002 / 19.233 |
| 12 线程压力 | 26.391 / 28.250 | 25.891 / 25.797 | 33.662 / 50.695 | 44.772 / 27.748 |
| 单核固定竞争 | 16.828 / 17.500 | 16.203 / 15.625 | 46.521 / 51.449 | 45.039 / 41.844 |

普通环境整组 CPU 两轮分别降低约 8% / 4%，12 线程压力组降低约 2% / 9%。这支持该 C 实验减少部分整组计算成本，不能推导每个场景的每个延迟分位数都改善。

逆向结果没有丢弃：普通环境长组字 P95 两轮均升高，mean 为 A 轮下降、B 轮升高；普通输入提前上屏开启的 A 轮 P50 也略升。12 线程压力 A 轮该普通输入 mean / P95 / P99 均回升，C 实验版整组墙钟 44.77 秒也高于原版 A 的 33.66 秒；原版 B 的墙钟又升至 50.70 秒，其中提前上屏关闭的普通输入出现 max=618.93 ms，长组字出现 max=334.42 ms。未捕获这些尖峰时的系统调度、缺页或其他等待栈，因此原因未定，不能仅以“环境噪音”排除代码影响。

最初固定核心、12 个竞争线程的试验超过负载程序 90 秒的持续上限，脚本按门禁拒绝该结果；其 `next-pinned-before-a.jsonl` 和时间记录保留，未混入有效表格。随后才改用同核心单线程竞争，另存为 `next-pinned-single-*`，没有覆盖原试验。

这些记录对应未采用的 C 三项合并实验。后续专用长输入对照没有支持保留父桶借用，因此该项已撤回；上述改善与回退均保留，不作为B 两项实验版的性能证据。
