## 本机注册验证

随后按用户授权在 ARM64 Windows 本机注册了 x64 和 x86 普通 DLL，安装匹配
服务端。两种架构从注册表创建 COM 对象成功，实际模块文件字节与预期 DLL
相等，已安装二进制 SHA256 与隔离测试产物一致。服务端 ping、candidate_ui
protocol=1 查询通过；仅做状态查询，没有注入按键。默认输入法和已有顺序保留。
未提供原生 ARM64 DLL，也未部署整句/神经模型。

x86 返回 System32 路径别名，初次字符串路径断言失败；经 WOW64 文件字节
比对后通过。安装脚本最后的状态快照停顿，停止该脚本后由独立进程完成
注册表、文件哈希、服务端路径和输入法顺序核验。

真实 Pain 打字、实际模型分页/异步换序/提前上屏、真实焦点切换和断线恢复
仍待实机操作验收。保留双窗；无宿主鼠标选词，不宣称完整 UILess。

## 构建问题记录

Linux ARM64 服务端受上游 AVX2 条件编译阻塞，改为交叉构建 Windows x64。
GNU x86 不使用上游定制 LLVM CRT 入口 shim；该 shim 现在由 feature 显式启用。
Rust 增量缓存曾出现编译器内部错误，禁用增量后构建通过。
首轮 Pain fixture 在断言通过后因 D2D 资源清理退出异常，修正后复验通过。
原始日志、哈希和本机安装记录保存在本地 `evidence/`，不纳入源码提交。
