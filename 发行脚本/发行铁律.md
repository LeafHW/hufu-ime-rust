# 发行铁律（2026-10-18 立此存照）

> 起因：v1.8.7 打包只出了 zip、漏了单 exe 安装包（用户质询「到底写没
> 写进规则」）。事实：exe 发行线一直在（`platform/windows/setup/
> build-setup.ps1`，1.8.1–1.8.6 每版都有 `HuFuSetup-*.exe`），但**从未
> 有任何一页文档把「完整发行=两条产物缺一不可」写成硬规则**，全靠执行
> 者记忆。本文件即是那条规则。漏一条=发行未完成，不许说「打包完成」。

## 一次完整发行 = 以下全部，顺序固定

1. **zip 发行线**：`发行脚本\pack.ps1 -Version x.y.z -NoModel`
   → `hufu-发行\HuFu虎符输入法-vx.y.z-无模型.zip`（核验全绿才算过）
2. **exe 发行线（rust 轨）**：
   `platform\windows\setup\build-setup.ps1 -Version x.y.z -Engine rust`
   → `hufu-发行\HuFuSetup-x.y.z.exe`（+ SHA256）
   ——**必须带 `-Engine rust`**（v1.8.3 起公开发布轨，安装全程零
   PowerShell 子进程；Defender 误报案闭环）。脚本参数默认值 `ps1` 是
   **回滚轨**——不带 `-Engine` 打出来的 exe 安装时会弹蓝色 PowerShell
   窗（v1.8.7 事故实锤：漏参出 PS 轨，用户装时看到蓝窗）。血律 PS 三件
   仍随包（zip 线共用 + 回滚），但发行件永远走 rust 轨。
   **pack.ps1 一跑完必须立刻跑这条**；产物缺 exe = 发行失败。
3. **git**：tag `vx.y.z` + 推 GitHub（分支与 tag 都推）。
4. **用户实测定版后**（不是打包时）：zip 复制进 `基线包\` 作下一版基线。

## 判定「发行轨」的唯一依据

**交付报告.md 的发布指纹表**（哪版、什么轨、SHA256），不是脚本参数
默认值。回滚轨做参数默认是历史包袱——查轨看表，别信默认。

## 边界与红线（既有约定，此处汇总）

- 不改 `pack.ps1`（zip 线原样）；exe 线的改动只落在 `setup\` 目录。
- 「打包完成」这个词只允许在 **zip + exe 双产物都在** 时使用。
- 两线共用同一 `打包源`（pack.ps1 同步的二进制与码表），**必须先 pack
  后 setup**（顺序反了会把旧二进制打进 exe）。
