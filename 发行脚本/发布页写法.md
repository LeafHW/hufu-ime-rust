## 规矩

1. **先拉上一版 body 照抄骨架再改内容**（API：GET /releases/tags/vX.Y.Z）——不凭记忆自创结构。
2. **覆盖面 = 上一个 release 到本次的全部更新日志条目**，逐条核对，漏了要挨骂（候选右键菜单那次；v1.8.7 模型段漏这次）。
3. **简洁**：主题归并、粗体关键词打头。
4. **终态口径**：被后续推翻的条目只写最终语义。
5. **模型段必带且原文照抄**：ModelScope 链接（国内直连、免登录）+ 目录位置 + **无需重启**（别写「要重启」）。2026-11-04 起模型统一放 ModelScope（`leafyin/hufu-ime` → `模型.rar`，550,479,428 B，sha256 `ca32f77a…`），GitHub「模型文件」页只作备用，新发布页一律用 ModelScope 直链。
6. **附件 = 单个 exe**（`HuFuSetup-vX.Y.Z.exe`，ASCII 名）；zip 不上发布页，验证定版后进本地 `基线包\`。
7. SHA256 不进发布页——入 `platform\windows\setup\交付报告.md` 发布指纹表。
8. 发布方式：无 gh CLI，用 token 走 REST API（PATCH /releases/{id}、上传走 uploads.github.com；PS 传 JSON 一律落盘文件 `--data-binary @file`，别内联——引号会被吞）。
9. 发布完自检：名字带「HuFu 虎符输入法」全称、四段骨架 grep 一遍、模型链接可解析、附件名/大小/状态终验。
