多宿主卡窗补全+孤儿组段兜底+Caps 默认回正（二十一修）

【问题一·多宿主复现】用户实测关闭「上屏后延时收候选」后，退场动
画中快打新编码在 QQ/Typora/VSCode 仍候选永存（此前只修了记事本
走的渲染分支）。根因：update_ui 有两个常规渲染分支（L4029 与
L4333），十七修只给前者补了「真实键入帧打断」——后者（QQ/VSCode/
Typora 等宿主走的路径）漏网，其 raw 同为编码行剥离值（inline_
preedit 默认开恒空），show 内部打断条件不生效。
【修】第二分支同款补 interrupt_effects（raw_state 真值触发）。
【问题二·30ms 极限快打竞态】30-40ms 键距偶发复现（diag 实锤：i 的
候选窗正确打断退场并显示，此后 3 秒完全静止——无 hide、无空帧，
poll 被 raw_last 拦截静默）。根因：DLL 的 raw_last 是本地缓存，
server 侧组段被外部清掉/空帧丢失时它成孤儿，「有编码不消失」的
收窗拦截被孤儿变成永久显示。
【修·双源判定】Shared 新增 srv_raw_empty_since（poll_tick 每 40ms
记录 server 侧 raw 连续空时长）；poll_collapse_stale 拦截条件改为：
raw_last 非空且 server 侧也连续空超 800ms = 孤儿，解除保护照常收
窗。正常打字 server 几十 ms 内必有 raw，800ms 阈值不误伤「思考中
编码在手」（回归实测：编码在手 2.5s 窗口仍在=不变量保住，ESC 正
常收）。
【问题三·Caps 默认】caps_action 默认误设 Clear（清屏），回正
Switch（切英文）；老安装 config 已显式写值不受默认影响（本机
config.json 已同步改回 Switch）。
【验证】记事本/VSCode/QQ ×（50/40/30ms 键距 × 单键/双键序列）共
20+ 轮快打全过（上屏后探测 0-1/18=动画尾巴正常）；编码在手 2.5s
保护不误伤；caps 配置生效。
